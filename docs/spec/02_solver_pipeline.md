# 02. 解析パイプラインと ngspice 連携

## 1. パイプライン全体

```
 Project(JSON) ─► Geometry ─► Mesh ─► Plasma params ─► Netlist ─► ngspice ─► Raw vectors ─► Post ─► Results(HDF5)
                                   ▲                      ▲                                   │
                                   │  密度/温度更新 (Level 1)│  自己バイアス・電力指定の外側反復        │
                                   └──────────────────────┴───────────────────────────────────┘
```

- **Mesh**：01 章 §2 の規則で径方向・軸方向セルを生成し、幾何量（面積、長さ、高さ $\zeta$、チェーンのインダクタンス）を確定します。プラズマパラメータに依存しません。
- **Plasma params**：$n(r), T_e, \nu_m, n_s, h_l$ 等から各セルの要素値を計算します。
- **Netlist**：テンプレートから ngspice ネットリスト文字列を生成します（§2）。常に人間が読める形で保存・エクスポート可能です。
- **ngspice**：共有ライブラリとして **ワーカプロセス**内で実行します（§4、03 章）。
- **Post**：波形から時間平均量・スペクトル・加熱・診断量を計算します（§5）。
- 外側反復（§3.3、§3.6、§6）はワーカ内で閉じて行い、GUI には進捗だけを返します。

## 2. ネットリスト生成

### 2.1 命名規約

| 対象 | ノード/素子名 | 例 |
|---|---|---|
| 電極ポート | `W`, `F`, `T`, `0`（接地） | — |
| 下部スタック中間ノード | `S{k}_{i}`（層 $k$ 上面、セル $i$） | `S1_12` |
| 下部表面ノード | `Sb_{i}` | `Sb_12` |
| バルクノード | `B_{i}_{j}`（$j = 1..N_z+1$） | `B_12_1` |
| 上部表面ノード | `St_{i}` | `St_12` |
| 上部導体ノード | `T_{i}` | `T_12` |
| 磁束チェーン補助ノード | `A_{i}_{k}`（セル境界 $i$、レベル $k \ge 1$；$k=0$ は接地 `0`） | `A_12_2` |
| シースサブサーキット | `Xshb_{i}`, `Xsht_{i}` | `Xshb_12` |
| 径方向ブランチ素子 | `{E,L,R,C,V,F}r_{i}_{k}` | `Er_12_2` |
| 外部回路素子 | 先頭に `ext_` | `ext_CbW` |

- インデックス $i$ は 1 始まり。セル境界 $i$ はセル $i$ と $i+1$ の間。
- 生成されたネットリストの先頭には、プロジェクト名、生成日時、プロジェクトのハッシュ、主要パラメータの要約をコメントで出力します。

### 2.2 サブサーキット

```
.subckt sheath P W  A=1 ns=1e16 Te=3 beta=0.5 s1=1e-4 Vmin=6 Rst=1 Ii=1 Ie0=1
* 電子欠乏シース: P=プラズマ側, W=壁側, V=V(P,W)>=0
.param e0=8.854187817e-12
.param Kq={e0*A*Te**beta/(s1*(1-beta))}
Csh  P  M  Q = 'Kq*pow(max(V(P,M)+Vmin, 1e-3*Vmin), 1-beta)'   ; 電荷ベース非線形容量
Rst  M  N  {Rst}                                               ; 確率的抵抗（容量経路に直列）
Vsc  N  W  0                                                   ; 容量経路電流のセンス
Iion P  W  {Ii}                                                ; イオン電流 P->W
Bel  W  P  I = 'V(P,W) >= 0 ? Ie0*exp(-min(V(P,W),60*Te)/Te) : Ie0*(1-V(P,W)/Te)'
.ends
```

- `Q(V)` は容量自身の端子電圧 `V(P,M)` の関数とします（$R_{stoc}$ による電圧降下はシース電圧の数 % 以下で、$Q$ の引数に用いる電圧の差は無視できます）。
- `Q=` 形式（電荷式）の挙動容量を用いることで電荷保存が保証されます。採用する ngspice 版で `Q=` が使えない場合は、
  補助容量と制御源による等価回路（`E` で $Q(V)/C_0$ を作り、`C_0` に流れる電流を `F` で本線に写す）に自動で切り替えます。
- 指数関数は引数を $60\,T_e$ でクランプし、$V<0$ では線形外挿します（01 章 §3.2）。
- `Bel` の三項演算子は ngspice の構文規則（`?` の前に空白）に従います。

バルク軸方向セグメント、層（R‖C）、径方向ブランチはインライン生成（サブサーキットにしない）とし、
値をコメントで併記します。

- `F` 源は「`0` からソースを通って `A_k` へ」電流を流すため、チェーンを $A_k \to A_0$ 向きに包含電流が流れます。
- `E` 源は $+r$ 方向の電圧降下として起電力を挿入します。
- チェーンの基準 $A_0$ は接地ノード `0` そのものとし、浮遊ノードを作りません。
- 数値は例であり、実装は上記の式から自動計算します。

### 2.4 外部回路の生成

```
* ---- external circuit : port W
Bext_srcW  nWs 0  V = 'VW1*min(1,time/tramp)*sin(2*pi*fW1*time+phW1) + VW2*min(1,time/tramp)*sin(2*pi*fW2*time+phW2)'
Lext_fW    nWs nWb  {Lfeed_W}
Cext_bW    nWb W    {Cb_W} ic={Vdc_W}
Cext_sW    W   0    {Cstray_W}
* ---- port F : cap_to_gnd tuning
Cext_tuneF F 0 {Ctune_F}
Cext_WF    W F {C_WF}
.ic v(W)={Vdc_W} ...
```

- 電源はランプ付き多トーン `B` 源（電圧源モード）で記述します。AC 解析では同じ振幅・位相を持つ `V ... AC` 源に置き換えます。
- 電力指定（Phase 2）は外側反復で振幅を決めるため、ネットリスト上は電圧源です。

### 2.5 線形（AC）モードのネットリスト

- シースサブサーキットを `C_lin` ＋ `R_stoc` の直列（電流源・ダイオード無し）に置き換えます。
- $C_{lin}$ は推定 RF 振幅 $V_1$ における $Q(V)$ の基本波成分から求めます：
  $C_{lin} = Q_1/V_1$、$Q_1 = \frac{2}{T}\int_0^T Q\big(V_1(1+\cos\omega t)\big)\cos\omega t\,\mathrm{d}t$。
  $V_1$ の初期推定は印加電圧の 1/2 とし、AC 解の $|V_{sh}(r)|$ で更新して 2〜3 回反復します（準線形）。
- 多周波の場合は周波数ごとに `.ac` を実行して重ね合わせます。
- `.ac lin 1 f f` で単一周波数の複素解、診断用に `.ac dec 50 1e6 1e9` で PSR・実効波長を検出します。

### 2.6 ユーザ定義ネットリストの挿入

- プロジェクト JSON の `circuit.extra_netlist`（文字列）を、外部回路セクションの末尾にそのまま挿入します。
- 使用できるノード名は `W`, `F`, `T`, `0` と、`u_` で始まる任意の新規ノード名。素子名は `ext_u_` を接頭します（衝突回避のため自動付与）。
- `.model`、`.subckt` の定義も可。`.tran`/`.ac`/`.option`/`.control` は禁止（生成側で管理）。禁止文を含む場合は検証エラーにします。

## 3. 解析モード

### 3.1 AC（線形小信号）

- 目的：定在波プロファイル、$\lambda_{eff}$、PSR、線形加熱分布の**瞬時プレビュー**。密度反復の内側ループ。
- 出力：各ノード電圧・ブランチ電流の複素振幅、$|V_{sh}(r)|$、$\arg V_{sh}(r)$、$J_z(r)$、$J_r(r,z)$、$B_\phi$、線形加熱 $\tfrac12|I|^2 R$。
- 所要時間：ミリ秒〜1 秒。

### 3.2 TRAN（非線形時間領域）

| 設定 | 既定 | 説明 |
|---|---|---|
| `pts_per_cycle` | 200 | 最高周波数の 1 周期あたり最大時間刻み $t_{max} = T_{min}/N_{pts}$ |
| `ramp_cycles` | 3 | 電源振幅の立ち上がりランプ |
| `cycles_min` / `cycles_max` | 10 / 200 | 周期定常判定を始める最小周期数と打ち切り |
| `meas_cycles` | 4 | 測定窓（最低周波数の周期単位） |
| `pss_tol` | $10^{-3}$ | 周期定常判定の相対許容値 |

- **基本周期**：複数周波数の場合、基本周期は $1/\gcd(f_k)$（例：2 MHz ＋ 60 MHz → 500 ns）。周期ごとの統計はこの単位で取ります。
- **周期定常判定**：各基本周期の終わりに、電極電圧 DC 成分、RF 振幅、散逸電力、代表セルのシース DC 電圧を評価し、
  直近 3 周期の相対変化がすべて `pss_tol` 未満なら定常とみなし、さらに `meas_cycles` だけ計算して停止（`bg_halt`）します。
- **出力**：測定窓の全ノード電圧・センス電流（可変刻み）。それ以前は周期統計のみ保持します。
- **多周波**：測定窓は基本周期の整数倍。LF の 1 周期に HF 数十周期が含まれるため計算量は増えます（§7）。

### 3.3 自己バイアスの外側反復

ブロッキング容量 $C_b$ を持つ電極では、DC 自己バイアスへの収束時間 $\tau \sim C_b R_{eff}$ が RF 周期の数百〜数千倍になり、
素朴に回すと計算時間を支配します。そこで：

1. **Stage A**：$C_b$ を $\kappa_b$（既定 0.02）倍に縮小したネットリストで `cycles_A`（既定 30）周期計算し、$C_b$ 電圧の終値を $V_{dc}^{(0)}$ とする。
2. **Stage B**：真の $C_b$ と `ic=V_dc` を用いて `cycles_min` 周期計算し、測定窓での $C_b$ 平均電流 $\langle I_b\rangle$ を評価する。
3. $\langle I_b\rangle$ が RF 電流振幅の $10^{-3}$ 未満なら終了。そうでなければセカント法で $V_{dc}$ を更新し 2 へ（最大 4 回）。
   複数電極（W, F 双方に $C_b$）では Broyden 更新を用います。
4. 最終の Stage B を本番の TRAN として採用。

オプション `dc_bias.method = "scaled_cb_only"` で Stage A の結果をそのまま採用する高速モードも用意します（LF 成分の波形が多少変わることを注記）。

### 3.4 SC（自己無撞着密度、Phase 2）

§6 の反復。内側ループは AC モード、収束後に TRAN で確定。

### 3.5 SWEEP

- 任意のプロジェクトパラメータ（JSON パス、例 `circuit.fr_tuning.C`）に対する 1D/2D スイープ。
- 各点は独立ジョブとしてワーカに並列投入（03 章）。結果は親 HDF5 の `sweep/` 以下に集約。

### 3.6 電力指定駆動（Phase 2）

- 目標供給電力 $P_{tgt}$ に対し、電圧振幅 $V_1$ をセカント法で更新（$P \propto V_1^2$ を初期勾配に）。通常 3〜4 回。
- 多電極では電極ごとに独立に扱い、交互更新（相互作用が強い場合は Broyden）。

## 4. ngspice 実行

### 4.1 形態

- **ngspice 共有ライブラリ**（Windows：`ngspice.dll`、Linux：`libngspice.so`）を **ワーカプロセス**にロードして使用します（`sharedspice.h` API）。
  - `ngSpice_Init(SendChar, SendStat, ControlledExit, SendData, SendInitData, BGThreadRunning, user)`
  - `ngSpice_Circ(lines)`：ネットリストをメモリから投入（ファイル I/O 不要）
  - `ngSpice_Command("bg_run")` / `"bg_halt"`：バックグラウンド実行と停止
  - `SendData` コールバック：受理された時間ステップごとに全保存ベクトルを受信 → 周期統計と測定窓の蓄積
  - `ngGet_Vec_Info`：停止後の最終ベクトル取得（AC 解析結果など）
- ライブラリはプロセスごとに 1 インスタンスという制約があるため、**並列実行はワーカプロセス数で**行います。
- ngspice がクラッシュしても GUI は影響を受けません（プロセス分離）。
- 対象版：ngspice **45 以降**を想定し、開発時点の最新安定版（47、2026 年 8 月）で検証します。`Q=` 形式容量の可否は起動時に自己テストで確認し、不可なら §2.2 の代替回路へ切り替えます。
- 代替実行形態として、バッチモード（`ngspice -b -r out.raw`）＋ rawfile 読み込みもサポートします（デバッグ・再現用）。

### 4.2 進捗・キャンセル

- ワーカは基本周期ごとに JSON 行（`{"cycle": k, "metrics": {...}, "converged": false}`）を標準出力へ流します。
- GUI からのキャンセルはワーカへのシグナル（またはパイプ経由コマンド）→ `bg_halt` → 途中結果を保存して終了。

### 4.3 ngspice オプション既定値

```
.options reltol=1e-3 abstol=1e-10 vntol=1e-6 chgtol=1e-16 trtol=7
.options method=gear maxord=2 itl4=50 gmin=1e-12
.options klu            ; 利用可能な版のみ（未対応なら無視して Sparse 1.3）
.tran {tmax} {tstop} 0 {tmax} uic
.save all
```

- `uic` と `.ic` により、シース電圧の初期値（$\approx$ 印加振幅）を与えてゼロ電圧（容量が極大）からの立ち上がりを避けます。
- 収束失敗（`timestep too small`）時は、(1) ランプ周期を 2 倍、(2) `reltol` を 3 倍、(3) $V_{min}$ を 2 倍、(4) `method=trap` の順に自動再試行し、ログに残します。

### 4.4 データ量の管理

- `.save all` は約 500〜1500 ベクトル。測定窓 4 周期 × 200 点では数 MB、多周波（30 HF 周期/基本周期）では数十〜百数十 MB。
  コールバックで受信した測定窓以外のデータは周期統計へ縮約して破棄します。
- 結果の時系列は、等間隔グリッドへの再サンプル版（FFT 用）と、必要に応じて元の可変刻み版の両方を保存できます（既定は再サンプル版のみ）。

## 5. 後処理

1. **再サンプル**：測定窓を $N_{pts}$ 点/周期の等間隔グリッドへ線形補間。
2. **時間平均**：可変刻みデータに対する台形則（電力・DC 値）。
3. **スペクトル**：基本周期長の FFT（窓関数なし、整数周期）→ 高調波振幅・位相。PSR 励起の指標として $V_{sh}$ の高調波比を出力。
4. **加熱・電力**：01 章 §7 の各量。電力収支誤差を `power_balance_error` として記録し、1 % 超は警告。
5. **シース量**：$\langle V_{sh}\rangle$、$V_{sh,1}$、$\bar s$、$s_{max}$、$z_s(r)$、$\theta(r)$。
6. **診断量**：$\omega_{pe}, \lambda_D, \delta, \nu_m, \omega_{PSR}, \lambda_{eff}, kR, \delta/(l_p/2)$。
7. **不均一性指標**：01 章 §9。
8. **2D マップ**：$p_{ohm}(r,z)$、$|J_r|(r,z)$、$|J_z|(r,z)$、$|B_\phi|(r,z)$ をセル中心値で出力（GUI で補間表示）。

## 6. 密度反復（Level 1）の擬似コード

```
n = initial_profile()                      # Level 0 と同じ指定
Te = particle_balance(n, gas, p, geometry)
for k in range(max_iter):
    params = plasma_params(n, Te)          # ns, Le, Re, Rstoc, Ii, Ie0, Q(V), delta など
    sol = solve_AC(mesh, params, circuit)  # 準線形反復込み
    Se = heating_profile(sol)              # W/m^2, 径方向
    n_hat = radial_power_balance(Se, Te, geometry)   # 三重対角解
    res = max(|n_hat - n| / n)
    alpha = adapt(alpha, history)          # 振動検出で半減, 単調なら 1.5 倍（上限 0.8）
    n = (1 - alpha) * n + alpha * n_hat
    Te = particle_balance(n, ...)          # 弱依存。数回に 1 回で可
    report(k, res, n, Te)
    if res < tol: break
sol_tran = solve_TRAN(mesh, plasma_params(n, Te), circuit)   # 最終確定
Se_tran = heating_profile(sol_tran)
if options.refine_with_tran:               # 任意: TRAN ベースで 1-2 回補正
    n = relax(n, radial_power_balance(Se_tran, Te))
    sol_tran = solve_TRAN(...)
```

## 7. 性能目標

| ケース | 規模 | 目標時間（デスクトップ 1 コア） |
|---|---|---|
| AC 1 周波数 | $N_r = 39$, $N_z = 1$（未知数 ~1000） | < 0.3 s |
| AC 周波数掃引 200 点 | 同上 | < 5 s |
| TRAN 単一周波数（自己バイアス反復込み） | 同上、約 60 周期相当 | 10〜60 s |
| TRAN 2 周波（2 + 60 MHz） | 同上、LF 20 周期 | 2〜10 min |
| TRAN 多層バルク | $N_z = 6$（未知数 ~2500） | 上記の 2〜3 倍 |
| SC 反復 | AC 内側 20 回 ＋ TRAN 1 回 | TRAN 単体 ＋ 10 s 以内 |

- 実測は M1 のベンチマークで確認し、超過する場合は (a) 保存ベクトルの削減、(b) `pts_per_cycle` の適正化、(c) シース要素の XSPICE コードモデル化（C 実装・解析的ヤコビアン）を検討します。

## 8. 数値的な注意点

- **剛性**：シース容量（$10^{-10}$ F）とチェーンインダクタ（$10^{-11}$ H）の時定数は fs オーダですが、Gear 法（陰解法）で安定。`maxord=2` で数値減衰を抑えつつ高調波を保ちます。
- **制御源の条件数**：`E`/`F` の利得は 1 で、行列の条件数を悪化させません。
- **電圧源ループ**：`E` と `V`（センス）が直列に並ぶ上部導体ブランチは、両端が容量・シースで他ノードに接続されるためループになりません。
- **電荷保存**：`Q=` 形式を用い、`C=` 形式（電荷非保存）は使いません。単体テストで 1 周期の電荷積分がゼロに戻ることを確認します。
- **スケール**：電圧 $10^2$〜$10^3$ V、電流 $10^{-3}$〜$10^2$ A、$L$ $10^{-11}$〜$10^{-7}$ H、$C$ $10^{-13}$〜$10^{-6}$ F。倍精度で問題ありませんが `chgtol`、`abstol` は上記規模に合わせます。
- **再現性**：ネットリスト・オプション・ngspice 版・プロジェクトハッシュを結果ファイルに保存し、同一入力で同一結果が得られることを保証します。
